# Training throughput notes

The training path is designed to keep H100s busy rather than serialize them on Python bookkeeping.

- GPU MCTS runs in static workspaces padded to a few batch widths; a whole simulation (descent, environment step, network evaluation, backup) is shape-static and sync-free, so it replays as one CUDA graph per (width, depth bound). The environment step is made of masked whole-batch writes. Measured on an H100: 8192 games in 240 s against 399 s eager and about 520 s before the rewrite; graph capture costs about 11 s per run.
- Self-play keeps repetition history and replay records on-device. Planes are compacted to uint8 before the one end-of-batch host transfer. Finished games are removed as before; games that hit the ply safety cap are discarded instead of being labelled as draws.
- Replay shards omit the all-3 Q tensor (`q_default=3`) and store their stable train/validation partition once. Exact shards use the same uint8 plane representation and uint8 WDL/Q labels. Current-version exact shards trust their recorded partition, while legacy shards are still reclassified safely.
- The learner stores the replay/exact corpus in compact dtypes. On CUDA it keeps the full corpus on-device when it fits with a configurable reserve; otherwise it can pin the compact host corpus. CUDA training uses BF16, channels-last convolutions and fused, capturable AdamW, and the whole training step (forward, loss, backward, optimizer) replays as one CUDA graph with static batch buffers; the cosine schedule drives a device-side learning-rate tensor. There is no torch.compile: profiled eagerly the step was CPU-bound, and the graph removes exactly that.
- Model files remain inference-only. AdamW moments are published separately as `<model>.opt`, so subsequent learner generations can retain optimizer history without making actor/model downloads larger. The per-generation cosine schedule intentionally restarts at the requested learning rate.
- Actor replay compression defaults to gzip level 1 and reports compression time separately, making it visible when post-processing rather than GPU search becomes material.

Useful switches: `SELFPLAY_GRAPHS`, `SELFPLAY_CHANNELS_LAST`, `SELFPLAY_PROFILE`, `DISTILL_GRAPH`, `DISTILL_PROFILE_STEPS`, `DISTILL_GPU_DATA`, `DISTILL_GPU_RESERVE_GB`, `DISTILL_PIN_MEMORY`, `DISTILL_CHANNELS_LAST`, `DISTILL_FUSED_ADAMW`, `DISTILL_RESET_OPTIMIZER`, `DISTILL_PERSIST_OPTIMIZER`, and `C4_REPLAY_GZIP_LEVEL`. Inference networks run with BatchNorm folded into the convolutions (`model.fold_batchnorm`).

These are throughput changes, not new game rules. Existing model/table binaries are not regenerated by the code change. Performance-sensitive CUDA paths must be benchmarked on the target GPU; every optimization has an eager/CPU fallback and correctness regressions run without requiring a GPU.
